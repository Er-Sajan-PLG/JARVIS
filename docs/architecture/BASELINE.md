## Known issues — NOT to be fixed in this migration wave

1. **LLM-less primary endpoint**: `POST /api/v1/chat/completions`
   (`app/adapters/http/router.py:63-112`) runs intent → plan → execute and returns plan-status
   JSON. It never calls an LLM and never returns generated text. Only the web-console path
   (`app/adapters/web/router.py:762-765`) generates text. (Fix scheduled: Migration Plan Step 5.)
2. **Phantom `search_web` tool**: `app/brain/analyzer.py:70` suggests `"search_web"` for
   `TOOL_SEARCH` intents, but no such tool is registered in `DEFAULT_TOOLSET`
   (`app/tools/__init__.py:40-53`). (Fix scheduled: Step 2.)
3. **Open bind**: `app/main.py:256` binds `0.0.0.0` by default while auth is disabled when
   `JARVIS_API_KEY` is unset (`app/adapters/http/router.py:41-44`, `app/main.py:259-264` warning).
   Operational hazard; out of scope for this code wave — operator must set the key.
4. **Split-brain secrets**: credentials live in four places — env/`.env`, `config.yaml`
   (`api_key: env:VAR` refs), `data/web_settings.json` (`app/adapters/web/settings.py:27`),
   and per-request header overrides (`app/models/factory.py:122-127`). No single inventory;
   rotation story UNKNOWN. Consolidation is a separate ADR, not this wave.
