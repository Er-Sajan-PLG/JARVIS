## 8. Follow-up: the pre-push signature stage (ADR-007)

Two branches had to be rebuilt during this session because merging `main` into a
PR branch made it unpushable. `githooks/pre-push` Stage 1 gated every commit in
`remote_sha..local_sha`, and merging `main` puts GitHub's own commits in that
range. Those are **PGP**-signed by GitHub and verify as `%G? = E` under this
repository's SSH-only configuration, so the hook reported them as unsigned and
refused — and Stage 0b refuses the force-push that would have made the branch
linear instead, so there was no recovery path.

Fixed in `githooks/pre-push`: Stage 1 now gates `rev-list <range> --not
--remotes=origin`, so published commits are not re-verified while every commit the
push introduces still is. Rejected: trusting `E` (indistinguishable from a
genuinely unverifiable commit) and installing GitHub's PGP key (third-party key
material in a provenance-focused trust store).

Recorded as **ADR-007** in `state/DECISIONS.md`, with the operational rule.

**Not yet landed:** the same rule belongs in `AGENTS.md` as a §4.3.2 next to the
pre-push hook docs. The write requires owner approval of an edit to a protected
agent-instruction file and the prompt timed out, so it is pending rather than
done. The hook's own header and Stage 1 comment carry the reasoning in the
meantime, and `tests/unit/test_prepush_verifies_only_new_commits.py` enforces the
behaviour.
